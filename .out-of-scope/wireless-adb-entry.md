# 桌面客户端的无线 ADB 连接入口

本项目不为桌面客户端做「填 IP 与配对码、点一下就无线连接手机」的图形入口。

## 现状：无线连接本来就能用，缺的只是界面

手动 `adb connect <IP>:<端口>` 之后，客户端会把那台机列出来并正常处理 —— 设备列表只跳过 `emulator-` 前缀，不按 transport 过滤。完整步骤写在 [docs/01-准备工作.md](../docs/01-准备工作.md) 的「不想插线：无线调试」，`adb_link` 的断线排查说明里也专门留了无线这一支。手机版 App 另有内置配对（#622、[ADR-0015](../docs/adr/0015-pairing-code-ocr.md)），覆盖「不想连电脑」这条路。

所以这张票要的不是新能力，是**不用开终端**。

## 为什么不做

**收益面比票面上看起来小。** 把 2026-11 之前连接类票逐张按诊断字段分层（16 张）：

- 真正落在 USB 驱动 / 枚举 / 线材层的只有 5 张（#348、#368、#256、#551、#252），占 31%；
- 其中两张最具代表性的「完全连不上」无线一点忙都帮不上 —— #294 是火绒拦本机 adb 进程，#263 是 Oppo Connect 自带的 adb 抢 5037 端口，无线连接用的还是同一个 adb server、同一个 `adb.exe`；
- 另外四张其实已经连上了：诊断里 `adb 设备：1 台（device）`，#535 / #257 是小米「USB 调试（安全设置）」拒绝 `INJECT_EVENTS`（归 #546 跟踪），#254 卡在读屏会话（0.2.7 已修），#326 是用户在列表里选错了设备。

**代价面有代码级证据，而且落在这个工具的主路径上。** 引擎的保持亮屏靠 `stay_on_while_plugged_in`（`tool/chan_fast.py` 的 `keep_awake()` 写 7），这个设置的语义是「**插电时**保持唤醒」，位 1 / 2 / 4 分别是交流、USB、无线充电。无线调试时手机不插电，这个位根本不生效，手机按系统超时息屏，adbd over TCP 随之断开 —— AGENTS.md 的「已知的坑」里「无线调试断开」那一行写的就是这个原因。

换算到现有数据：桌面版当前断线提示出现在 115 / 1866 份上报里（6.2%），锁屏相关失败 177 / 1866（9.5%，第二大失败原因）。无线不是把 6.2% 原样搬过去，是搬到一个更容易触发的环境里。

**掉线后的恢复成本也不同。** USB 掉线，用户手里有物理动作（重插）；无线掉线要回手机「关开无线调试 → 抄新端口 → 重新连」。而 `Connection` 确认断线后本段直接跳过、不重试（#293 定的口径），一次无线掉线就是这一段作废。

**要做就必须连保活一起改。** 只加一个连接对话框、不动 `keep_awake`，结果是把「连不上」换成「跑一半断」——后者对用户更难解释，对仓库是又一种失败形态。保活改造意味着在无线场景下改 `screen_off_timeout` 再还原，这又是一条「改了系统设置却没还原」的风险路径。

## 什么情况下会重新考虑

- 有报告者说明 USB 这条路**物理上走不通**（尾插损坏、只能用无线充电、设备根本没有 USB 口），那是刚需，比例不重要；
- 保活那一层被单独解决了（无线场景下手机不插电也能保持唤醒），新增失败面的前提就不再成立。
