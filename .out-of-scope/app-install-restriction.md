# 限制应用安装（防误装）

本工具不做「限制安装新应用」这一类功能：既不提供「禁止安装」开关，也不代为设置儿童空间 / 青少年模式的密码。

## 为什么超出范围

工具的动作只有三类：打开系统设置页拨开关、关闭通知渠道、`pm suspend` 挂起**已安装**的包。三类都拦不住一个新应用被装上——挂起只作用于已存在的包，不影响安装流程本身。

把「禁止安装」做成脚本，每条路线都有硬伤：

- **各家自带的儿童空间 / 青少年模式**能禁装、禁卸载，但开启前必须先设一个独立密码，而这一步只能在手机上人工完成。脚本最多把人送到入口——本工具的每个动作都以「点完能读回」为前提，送到入口不算做完。
- **`no_install_apps` user restriction** 需要 device owner 或 root。走 device owner 要清空设备账号再 `dpm set-device-owner`，与本项目「不 root、一次性 ADB、可还原」的约束直接冲突。
- **AppOps `REQUEST_INSTALL_PACKAGES`** 只关得掉「安装未知应用」，挡不住应用商店的安装，覆盖不了诉求。
- **自建 DPC** 等于常驻一个设备策略 App，**装上再删** 等于常驻一个监听进程。两者都不是本仓库「一次性 ADB 执行完就退场」的形态。

换句话说，这是**设备策略管理**，不是**广告与通知开关的审计**。需要常驻、需要 device owner、需要托管密码的限制，是另一种产品。

## 什么时候可以重新评估

如果产品路线改成常驻 App + device owner（那时它就不再是「跑一次就还原」的工具），或者 Android 开放了不经 device owner 就能设 `no_install_apps` 的路径，这条才有位置。

如果诉求是「长辈装了乱七八糟的软件」，本工具能覆盖的部分在别处：关掉应用商店的开屏推荐与推广位、关掉「精品应用推荐」一类通知渠道、挂起已经装上的预装包。
