只记 GitHub 上看不到的：同一类表象怎么判定、缺哪台机器的真机验证。逐条回复、标签变化、讨论过程都在 issue 里，这里不重复。

新增一批处理时加三行以内 —— 处理了什么类别、判据是什么、状态落在哪。细节留在 issue 与 PR 里；哪一版修了什么看 [CHANGELOG](../CHANGELOG.md)。

## 判据速查

看到这类现象，先按这条判：

| 表象 | 判据 | 代码 / 文档 |
|---|---|---|
| 卡在「正在连接手机读屏服务」，或某一步几秒内失败、退出码 1 | 先看日志有没有 `UiAutomation not connected`、`AccessibilityServiceAlreadyRegisteredError`。有就是读屏服务被别的工具占着（GKD、自动记账、另一个客户端、旧版 adb），不是机型不适配：要求退出其他工具只留一个客户端，仍失败重启手机。**这类报告常以「XX 没适配」的标题出现，不要当机型请求处理**（样本见 #323） | `tool/fast.py:79-95`；[排查说明](11-读屏冲突与功能通知保护.md) |
| 营销通知批量「未确认」 | ColorOS / 荣耀的系统管家渠道页由独立包承载；先确认页身份，再按回读判成功 | [归档记录](归档/CHANGELOG-0.3.0及更早.md) |
| 扫描出来的营销渠道明显太少，名字里带「消息」的整类不见 | 看渠道 ID 是不是厂商营销分类号（vivo `VPushChannel_0/4/6`）。是就该在清单里：分类号能越过跳过词，但营销关键词仍要命中；`VPushChannel_1/2` 是服务通知，仍应跳过 | `tool/channel_policy.py` 的 `VIVO_MARKETING` 与 `classify()` |
| 渠道 ID 是广告网络车道（`TencentAdNetCH1`、`ADroiUnion` 一类），名字不带营销词 | ID 命中广告网络名即进候选并越过跳过词；只认 ID 不认名，`unionpay` 这类不误伤 | `tool/channel_policy.py` 的 `AD_NETWORK` 与 `classify()`（ADR-0006 增补） |
| 能读到开关但点不动、写不进设置 | 小米系「USB 调试（安全设置）」没开；`input keyevent 0` 返回 `INJECT_EVENTS` 即判定被拒 | [小米清单](清单/小米-HyperOS.md) |
| 执行中途 `device not found` | 手机断了。等它回来重试一次，仍断开就停止并提示；不把空结果算成功 | `tool/adb_link.py` |
| 新机型「没适配」 | 先看诊断里「机型脚本」一行是不是借了同品牌参考脚本。借脚本走安全模式，入口改名就跳过，命中率低属正常，不等于适配失败 | [docs/04](04-给新机型写脚本.md) |
| 原生鸿蒙 | 只有 HDC，不在支持范围 | — |
| Windows 弹窗说「缺少 WebView2」，但装的是便携版 | 不一定真缺运行时。先看注册表 `HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-…}` 的 `pv` 在不在：在就说明运行时没问题，是解压出来的 `Python.Runtime.dll` / `ClrLoader.dll` 带 `Zone.Identifier`（MOTW）被 .NET 拒载，`import clr` 失败。对 zip 解除锁定后重新解压，或对解压目录跑 `Unblock-File`；安装版由安装程序写文件，不受影响 | `gui/winpreflight.py`（#228） |
