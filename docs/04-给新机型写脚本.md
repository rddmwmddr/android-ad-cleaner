# 04 给新机型写脚本

机型脚本记录「在哪个 App、点哪几个字、关哪几个开关」。它现在是**一份页面树数据**（`.toml`）+ 可选的**本机例外函数**（`.py`）：数据描述意图（有哪些页面、有哪些行、怎么进去、关哪些、留哪些），怎么翻页、怎么等待、失败了怎么收场由运行时统一做。录一台新机大多等于填一份数据，不再写一个程序（[ADR-0038](adr/0038-recipe-catalog.md)）。

这一页写给录制自己手机上那份数据的人：只用下面这些形状与名字，不读引擎源码也能写完。

## 机型脚本放在哪

```text
recipes/<家族>/<型号>/<型号>.toml     # 页面树数据（主体）
recipes/<家族>/<型号>/<型号>.py       # 本机例外函数（有才写；没有就不建）
```

`<型号>` 用 `adb shell getprop ro.product.model` 的输出，比如 `PLP120`、`M154FF`、`PNM-AN10`。`run.py` 按这个名字自动匹配。`<家族>` 取品牌的家族名（`entries.FAMILY`）：`xiaomi`（含 redmi / poco）、`oppo`（含 oneplus / realme）、`vivo`（含 iqoo）、`honor`、`huawei`、`meizu`、`samsung`。**型号身份以数据里的 `MODELS` 为准**，目录名只是落点；一份数据可声明多个型号（`models = ["M154FF", "2608BPX34C"]`）。

同型号出了新版系统、入口确实不同时，另放一份 `<型号>-<变体>.toml`（如 `PLP120-android16.toml`），`run.py` 只在变体的录制版本对得上时选它。

没有本型号脚本时，`run.py` 会找同品牌的脚本作参考，`recipe --ref` 才会跑，客户端里默认不勾。参考脚本、版本对不上的脚本都用**安全模式**跑：只关数据里点名的开关（`only` 或 `only_code`），不做整页全关。所以数据里尽量点名。

## 为什么每个型号要单独做

同一个品牌，系统小版本不同，设置页也会变。实测例子：

| 机型 | 系统 | 浏览器设置入口 | 视频设置入口 |
|---|---|---|---|
| Find N6 | ColorOS 16.0.9 | 底部 ☰ → 齿轮 | 我的 → 设置 → 个性化内容管理 |
| Find X9 Ultra | ColorOS 16.0.10 | 底部「我的」→ 设置 | 找不到「我的」 |

所以数据开头写明录制时的系统版本（`build`，和 `ro.build.display.id` 或小米的 HyperOS 版本号 `ro.mi.os.version.incremental` 的开头比对），版本不同时引擎会提醒并进安全模式。小米 / 红米 / POCO 一律写 HyperOS 版本号（`OS3.0.307.0`）：它们的 `ro.build.display.id` 报的可能是 Android 底包（`BP2A.250605.031`），底包整代机型共用一个号，写进 `build` 等于对所有同代机型都说「版本相同」，引擎也会把这种值直接当成没标录制版本（#942）。只录到底包、拿不到 ROM 版本号时 `build` 留空，未标版本的数据不参与跨型号借用。

**保护类开关**：「限制广告跟踪」「防止广告追踪」「关闭个性化推荐」「选择停用广告个性化功能」这类带否定词、和广告有关的开关，打开才是保护。否定词前允许「选择 / 選擇 / 点击 / 點擊」，简繁两种写法都认（#604）。运行时会把它们拨到「开」，数据照常把它们写进 `only`。

## 一份数据长什么样

```toml
model = "PLP120"
models = ["PLP120"]
build = "PLP120_16.0.9"          # ro.build.display.id 的开头

[[segment]]                       # 一段管一个分组，段名即台账与重试对齐的身份
name = "软件商店"
ops = [
  {kind = "start", pkg = "com.heytap.market", expect = ["我的"]},   # 拉起 App，落点不对就退一次
  {kind = "lib", name = "my_tab", args = ["我的"]},                 # 点底栏「我的」（底栏标签一律走 tab）
  {kind = "entry", text = "设置"},                                  # 进设置页（可选入口，找不到跳过）
  {kind = "gated", entries = ["隐私"], ops = [                      # 认「隐私」进子页，再关
    {kind = "off", only = ["个性化推荐"], page = "商店·隐私"},
    {kind = "back"},
  ]},
]

[[segment]]
name = "系统广告"
code = "local_system_ads"          # 表达不了的段：整段交给本机例外函数（见下）
```

一段 = 一个 `[[segment]]`，段体二选一：一串 `ops`（页面树），或 `code = "<本机策略名>"`（整段交给该机 `.py` 里的一个函数）。**段里每一步都经运行时的段执行入口**，段名进台账、客户端重试按它定位，所以段名要唯一、尽量与词库分组同名。

### 页面树能装在数据里的知识（op 种类，封闭白名单）

| kind | 作用 | 关键键 |
|---|---|---|
| `start` | 拉起 App / 指定页面 | `pkg` / `activity` / `expect` / `settle` / `foreground` / `budget` |
| `start_or_skip` | 拉起；落点被系统转去别处（命中 `dead_ends`）时按跳过收尾 | `pkg` / `activity` / `dead_ends` / `reason` |
| `skip_unless_installed` | 本机没装这个包就整段收尾（完成） | `command` / `contains` / `text` |
| `await_page` | 等页面认出来（门面 `p.await_page`） | — |
| `entry` / `require_entry` | 点可选 / 必需入口 | `text` / `scrolls`；必需的要 `miss_print`（缺了就整段失败） |
| `enter` | 点进去并确认换页（门面 `p.enter`，换页被吞会重试） | `text` / `scrolls` |
| `gated` | 认一串入口后执行子 ops | `entries` / `scrolls` / `ops` |
| `if_entry` | 认入口成功走 `ops`、否则走 `else_ops` | `text` / `scrolls` / `ops` / `else_ops` |
| `tap` / `require_tap` | 点一个文字（点不到继续 / 点不到即这一段失败） | `text` / `exact` / `scrolls`；必需的要 `miss_print` |
| `go` / `require_go` | 按文字导航并确认落点（失败继续 / 失败即这一段失败） | `text` / `expect`；必需的要 `miss_print` |
| `require_tab` | 点底栏标签，点不到即这一段失败 | `name` / `miss_print` |
| `off` | 关这一页点名的开关 | `only`（或 `only_code`）/ `keep` / `page` / `max_screens` |
| `off_required` | 读齐两屏 → 回页顶 → 点名断言都在 → 点名关 | `only` / `keep` / `page` / `contains` |
| `close_all` | 点 UI 上的「全部关闭」按键（整页全关） | `page` / `button` |
| `close_listed` | 读回这一页的开关 → 只留点名的、页上真有的行 → 整表关 | `names` / `page` / `miss_print` |
| `lib` / `require_lib` | 调共享库里的走法（见下） | `name` / `args` / `kwargs`；必需的要 `miss_print` |
| `return_lib` | 段的结局就是这个库调用的返回值（假 → 这一段记「未完成」） | `name` / `args` / `kwargs` |
| `code` | 段内某处调本机例外函数 | `name` / `args` |
| `scoped` | 作用域内临时置一个页面属性（如 `systemui_text`）后恢复 | `systemui_text` + `ops` |
| `back` / `top` | 返回 N 次 / 回到页顶 | `n` |
| `page` | 落点三段判据（包名 / Activity / 标题），实参照 `lib` 的形状原样交给 `rt.page` | `args` / `kwargs` |
| `shell` | 不经门面的读屏命令（`p.d.shell`），拉起设置页、`getprop` 这类原样下发 | `command` |
| `sleep` | 段内等待（走运行时时钟，用例不真等） | `seconds` |
| `press` / `app_stop` | 按键 / 停掉 App（`p.d.press` / `p.d.app_stop`） | `key` / `pkg` |
| `note_miss` / `miss_reset` | 记一次落空 / 清空落空计数（`p.note_miss` / `p.miss = 0`） | `text` |
| `dismiss` | 关掉挡路的弹窗与推广位（门面 `p.dismiss`） | — |
| `require_unlocked` | 锁屏就按这一段失败 | `miss_print` |
| `require_setting` / `if_setting` | 设置搜索直达：失败即这一段失败 / 按成败分岔 | `kw` / `entry` / `miss_print` / `ops` / `else_ops` |
| `require_focus` / `if_focus` | 按当前前台窗口断言 / 分岔（`match` 明写 `equals` / `starts` / `contains` / `icontains`） | `contains` / `text` / `match` / `miss_print` / `ops` / `else_ops` |
| `require_find` / `if_find` | 按找得到断言 / 分岔 | `text` / `exact` / `edge_ok` / `nav` / `miss_print` / `ops` / `else_ops` |
| `require_expect` | 几个 `p.expect_page` 短路 OR，全落空即这一段失败 | `calls` / `miss_print` |
| `if_lib` | 按共享库助手的返回值分岔（`settings_page` / `wait_page` / `tap_by_scroll` 那类布尔返回） | `name` / `args` / `kwargs` / `ops` / `else_ops` |
| `if_lib_any` | 几个助手短路 OR，第一个成功的走 `ops`、全落空走 `else_ops` | `calls` / `ops` / `else_ops` |
| `if_tap` | 按门面 `p.tap` 的返回值分岔（库里的 `tap` 失败即抛，不用于这里） | `text` / `exact` / `scrolls` / `ops` / `else_ops` |
| `skip` | 按约定跳过这一段（`rt.skip`），结局记「跳过」而非「未完成」 | `text` |
| `skip_in_safe_mode` | 安全模式下跳过本段（整页全关这类走到这里） | — |
| `fail` | 这一段失败并带原因，进失败段台账（`raise` 的失败出口；`return value=false` 只改结局不进台账） | `text` / `evidence` |
| `print` / `return` | 打一句人话 / 提前结束这一段（`value = false` 让这一段记「未完成」） | `text` / `value` |

这张表就是校验器的种类白名单 `tool/catalog/schema.py` 的 `OP_KEYS`：表里没有的 `kind`、某种 op 多写的键，装载期直接报错。`press` 与 `app_stop` 目前没有机型用到，留着是因为机型知识里确实会遇到；新增一种要先在 `OP_KEYS` 登记，判据是「≥2 机型用法」。

`off` 的 `only` 是**点名**：要么内联一串字面量，要么 `only_code = "<本机策略名>"` 指向例外函数算出名单——两者运行期都算点名，安全模式都不抑制。整页全关单列 `close_all`，不再靠「没有 only」推断。关一组点名的开关之前要核对齐全的段，用 `require_lib` 调库里的核对助手（缺一项就整段不动，报错带页面现场，#903）。

**schema 只装机型知识**（有哪些页面、有哪些行、怎么进去、关哪些、留哪些）；早退、中止、重试、失败收集、台账写完、页面快照这些**编排语义不进数据**，全机型同一套，由运行时做。看到某个 op 想表达的东西其实是编排语义，先按运行时语义确认，别往数据里塞。

同一段数据里段体写不下的（循环、坐标算法、按读到的开关收窄名单）走 `code = "<名字>"`，函数留在同名 `.py` 里；`if_*` 只覆盖「有界的一层分支」，多层嵌套的照样整段交给例外函数。

### 走法分派写在数据里（`[const]`）

家族库的同一个实现名在不同机型上走法不同（设置页入口、点行的匹配方式、读开关的口径、关一组开关的收尾……），选哪一档由数据顶层的 `[const]` 常量给，键名与库里的 `*_STYLE` 一一对应：

```toml
[const]
OPEN_SETTINGS_STYLE = "intent"     # 缺省档见 tool/recipe_nav.py；不写就是缺省档
CLOSE_NAMED_STYLE = "basic"
```

`_style()` 读到认不出的值当场报错，不静默回退（回退会点错入口）。库按**名字**回调的那几个钩子（段体里 `g["off_exact"]` / `g["close_named"]` 那种）没法写成字符串，用同名 `.py` 里的一行别名把实现绑回旧名，例如 `off_exact = off_exact_paged`——分派同样只在数据与本机文件里看得见，不靠运行时猜。

## 本机例外函数

数据表达不了的**真机型知识**（这一页的坐标算法、`dumpsys` 读数、在控件树上正则找图标……）写进同目录同名的 `<型号>.py`，由 `code = "<名字>"` 或 `only_code` 指向。例外函数是**普通函数**，`p`（设备面）与 `rt`（这一次执行）作为参数传入，不再靠隐式注入；导入它不产生任何设备动作。

```python
def local_system_ads(p, rt):
    p.start("com.hihonor.hiboard", ".settings.PASettingActivity")
    p.off(only=["推荐卡片"], page="负一屏·设置")
    if p.entry("隐私设置"):
        p.off(only=["个性化推荐"], page="负一屏·隐私")
        p.back()
    p.back()
```

例外函数里能用的 `p.*` 动作与原来一致（`p.start` / `p.entry` / `p.tab` / `p.off` / `p.back` / `p.find` / `p.settle` / `p.d.shell` ……）。几条必须守的：

- **别在例外函数里再抄一份段包装、前导、失败台账**：段名、失败收集、锁屏中止、退出码都由运行时统一管，抄回来的副本会盖住引擎那份，两代实现又要分叉。
- **按约定不跑**（型号 / 版本不符，或必须机主手动进入）用 `rt.skip(原因)`：引擎接住后只打一句「跳过」，记跳过台账，不进失败名单。这一段要用的 App 本机没装也归这一档。「先试直达、再走菜单」的助手要把跳过原样上抛：吞掉它，这一段会从跳过退化成菜单空跑或假失败。 <!-- rule:dev.recipes.skip-passes-through-helpers -->
- **整页关闭**（逐 App 的广告跟踪列表、应用建议卡片）用 `close_all`；安全模式下它按跳过收尾（只关点名的开关）。例外函数里做整页关闭时，第一句先 `if rt.safe_mode: rt.skip(...)`，判据与运行时同一档。 <!-- rule:dev.recipes.safe-mode-page-wide-skip -->

**只有当同一份例外在 ≥2 台机型出现时**才升格进家族库（`recipe_lib/<家族>.py`）或共享库（`recipe_lib/shared.py`）；单机专用的留在本机 `.py`。升格是机器守卫：同名实现出现在 ≥2 个机型又不在库里，CI 会红。本机例外的数量在 `check` / `status-json` 里可见（「本机策略：N 个」）——它是「例外悄悄变成常态」的报警，不是指标。

## 共享库与家族库：写哪、别写哪

跨机型复用的走法住在 `recipe_lib/<家族>.py` 与 `recipe_lib/shared.py`，数据用 `{kind = "lib", name = "<名字>", args = [...]}` 或 `{kind = "require_lib", ...}` 调用。**家族库**是只被同一家族用到的实现（例外在第二台机型重复出现时升格进来）；**共享库**是跨 ≥2 个家族在用的实现。**只是字面量不同**（标题名单、超时秒数）的，参数化后共用一份，数据里用 `args` 把值传进去。

新机型第一份数据**只往家族库加东西，或者什么都不加**：能直接用共享库里已有的名字就用；只服务这一台机的逻辑写成本机例外。把单台机的写法塞进共享库等于给一份数据造了家族库——守卫是「共享分节里的每个实现必须被 ≥2 个家族使用」（`dev.recipes.shared-sections`）。

发现引擎的某个原语（`p.off()` 的落点、`p.tap()` 的匹配、确认框的判定）在这台机上不对时，**不要在数据或例外里给引擎打补丁**：写成社区问题上报或直接修引擎（`tool/phone/`）。补丁留在机型侧，别家看不到它，引擎下一版还会盖掉。

## 写机型脚本的步骤

1. 用 `adapt` 流水线攒数据（下一节），或手动走一遍：

   ```bash
   python3 tool/fast.py -s S ls            # 看屏幕上有什么字、什么开关
   python3 tool/fast.py -s S tap 我的 设置   # 一步一步点进去
   python3 tool/fast.py -s S scan          # 到了设置页，列出所有开关
   adb -s S shell dumpsys window | grep mCurrentFocus   # 停在目标页时查 activity
   ```

2. 每段一个 `[[segment]]`，入口能直达（`start` 带 `activity`）就直达，省时也稳。
3. 表达不了的段写成 `code = "local_xxx"` + 同目录 `<型号>.py` 里的函数。
4. 跑一遍 `python3 tool/run.py -s S recipe 软件商店`，再跑全部，记下用时，填进 README 的机型表。
5. 用查漏对一遍同族的词库：`python3 tool/vocab.py gaps <家族>/<型号>`——列出同族别的机型关过、这份没写的词条。它是自查清单，不是缺陷报告。

## 适配辅助工具（adapt）

新机型没有数据时，用 `adapt` 四段流水线攒一份骨架（中间勾选 TSV 那一步由人做，不算一条命令）。四段都由人把关，工具不自动决定关哪些开关：

```bash
python3 tool/run.py -s S adapt survey                                          # 1. 只读试入口
python3 tool/run.py -s S adapt explore com.heytap.market com.heytap.browser    # 2. 只读探路
# 3. 编辑 探路-<型号>.tsv：末列「人工勾选」写「关」，挑出要关的开关
python3 tool/run.py adapt gen 探路-<型号>.tsv                                   # 4a. 生成 <型号>.toml 骨架（不碰手机）
python3 tool/run.py -s S adapt check 草稿-<型号>.toml                           # 4b. 安全模式自检
```

`survey` 拿同家族已验证过的直达页面逐条打开，报打不打得开、落在别处时实际停在哪个页面、命中了同分组的哪些词条，以及同族用过的 App 这台装了哪些。只读：不点开关，看到协议弹窗只标注。`explore` 逐个打开设置页和子页，列出像广告的开关；只读，不拨。

`gen` 把人工勾选的开关生成 `<型号>.toml` 骨架（`-o x.py` 仍可产旧的 Python 草稿）。骨架形状已经对：每段一个 `[[segment]]`，`start` 拉起 → `entry` 逐层进子页 → `off` 关点名的开关：

```toml
model = "PLP120"
models = ["PLP120"]
build = ""

[[segment]]
name = "com.heytap.market · 设置 > 隐私"
ops = [
  {kind = "start", pkg = "com.heytap.market"},
  {kind = "entry", text = "设置"},
  {kind = "entry", text = "隐私"},
  {kind = "off", only = ["个性化推荐"], page = "设置 > 隐私"},
]
```

`check` 用安全模式跑草稿（`.toml` 或旧 `.py` 都行）：只关点名的开关，找不到就如实报告「哪一步没做成」。它证明的只是「进得去、关得掉、回读确认」。

**草稿不是适配**：入口路径和开关标题全部来自探路读屏，未经人工逐步核对。自检通过后仍须人工在手机上核对每一步，再决定是否转为正式数据（补上 `build`、按下面「提交 PR」登记）。不要直接放进 `recipes/`：放进去会被当成本型号的正式脚本自动匹配。

## 提交 PR

1. 新建 `recipes/<家族>/<型号>/<型号>.toml`（有例外再建同目录 `<型号>.py`）。
2. 在 `docs/清单/` 对应品牌的清单里补上这个机型的差异。
3. 在 README 机型表里加一行，写明实测日期和用时。
4. 不要提交 `backups/` 目录，里面有你手机的应用列表和通知记录。

只碰机型脚本与清单的 PR 走「机型 / 清单类」的合并前检查；其中一条是「文档与生成器同步」——你的数据与 `adapt gen` 产出的骨架保持同形，这一页说骨架长什么样，生成器就该是那个样。四条的全文见 [docs/agents/issue-tracker.md](agents/issue-tracker.md) 的「Pull requests as a triage surface」。
