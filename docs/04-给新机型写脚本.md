# 04 给新机型写脚本

机型脚本是一个 Python 文件，记录「在哪个 App、点哪几个字、关哪几个开关」。有了机型脚本，同型号的手机几分钟跑完。

这一页写给录制自己手机上那份脚本的人：写的时候只用下面这些名字，不读引擎源码也能写完；引擎内部怎么把它们装起来，见 [ADR-0037](adr/0037-recipe-declarative-loader.md)。

## 机型脚本放在哪

```text
recipes/<家族>/<型号>/recipe.py
```

`<型号>` 用 `adb shell getprop ro.product.model` 的输出，比如 `PLP120`、`M154FF`、`PNM-AN10`。`run.py` 按这个名字自动匹配。`<家族>` 取品牌的家族名（`entries.FAMILY`）：`xiaomi`（含 redmi / poco）、`oppo`（含 oneplus / realme）、`vivo`（含 iqoo）、`honor`、`huawei`、`meizu`、`samsung`。型号身份仍以脚本里的 `MODELS` 为准，目录名只是落点。

脚本是一个普通 Python 模块：**导入它不产生任何设备动作**。段用 `@step("段名")` 声明，只有引擎真正开跑时才逐段执行，顺序按函数在文件里出现的先后。所以不要写成「模块一导入就开始点手机」的脚本——那种写法现在会在导入的那一刻执行，引擎看不见它，段过滤与重试也管不到。

同一份脚本适用多个型号时，在脚本里写 `MODELS = ["M154FF", "2608BPX34C"]`，这些型号都会用它。

没有本型号脚本时，`run.py` 会找同品牌的脚本作参考，`recipe --ref` 才会跑，客户端里默认不勾。参考脚本、版本对不上的脚本都用**安全模式**跑：只关 `only=[…]` 里点名的开关，不做整页全关。所以脚本里尽量写 `only`。

## 为什么每个型号要单独做

同一个品牌，系统小版本不同，设置页也会变。实测例子：

| 机型 | 系统 | 浏览器设置入口 | 视频设置入口 |
|---|---|---|---|
| Find N6 | ColorOS 16.0.9 | 底部 ☰ → 齿轮 | 我的 → 设置 → 个性化内容管理 |
| Find X9 Ultra | ColorOS 16.0.10 | 底部「我的」→ 设置 | 找不到「我的」 |

所以机型脚本开头写明录制时的系统版本（`BUILD`，和 `ro.build.display.id` 或小米的 HyperOS 版本号 `ro.mi.os.version.incremental` 的开头比对），版本不同时引擎会提醒并进安全模式。小米 / 红米 / POCO 一律写 HyperOS 版本号（`OS3.0.307.0`）：它们 `ro.build.display.id` 报的可能是 Android 底包（`BP2A.250605.031`），底包整代机型共用一个号，写进 `BUILD` 等于对所有同代机型都说「版本相同」，引擎也会把这种值直接当成没标录制版本（#942）。只录到底包、拿不到 ROM 版本号时 `BUILD` 留空，未标版本的脚本不参与跨型号借用。

`BUILD` 写具体（`OS3.0.308`）还是只写大版本（`OS3.0`），决定了这份脚本会被哪些没有专用脚本的机型借走：版本按前缀比，写细了对得上的机型少，写粗了对得上的机型多。写粗只影响这份脚本自己够不够贴——同族里录在更具体版本上的脚本会优先于它被选走（#969）。

同一型号出了新系统版本、入口确实不同时，不改原文件，另放一份 `recipe_<系统版本>.py`（已有 `recipe_os4.py`、`recipe_android15.py`、`recipe_android17.py`）。`run.py` 只在变体的录制版本对得上时选它，其余情况仍用 `recipe.py`；变体只在同型号目录里选，不影响别的机型。

入口名在新旧版本之间会变，脚本里可以写成「有就点、没有跳过」，用引擎注入的 `maybe()` / `p.entry()`。

**保护类开关**：「限制广告跟踪」「防止广告追踪」「关闭个性化推荐」「选择停用广告个性化功能」这类带否定词、和广告有关的开关，打开才是保护。否定词前允许「选择 / 選擇 / 点击 / 點擊」，简繁两种写法都认（#604）。`p.off()` 会把它们拨到「开」，脚本不用另外处理。

## 一段机型脚本长什么样

```python
from recipe_kit import step

BUILD = "PLP120_16.0.9"          # ro.build.display.id 的开头
MODELS = ["PLP120"]

@step("软件商店")
def _():
    p.start("com.heytap.market", expect=("我的",))   # 拉起 App；没落在有「我的」的页面就退一次
    p.tab("我的")                                 # 点底栏「我的」：底栏标签一律用 tab()，见下
    p.enter("设置")                               # 点「设置」并确认真的换页；被弹窗动画吞掉会重点（#286）
    if p.tap("隐私", exact=True):                 # 找到「隐私」就点，找不到会翻页
        p.off(only=["个性化推荐"], page="商店·隐私")   # 只关标题含「个性化推荐」的开关
        p.back()

def tail():
    print(f"\n回读确认 {rt.verified} 项", flush=True)

from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from recipe_kit import p, rt
```

**点底栏一律用 `p.tab("我的")`**（示例里那行就是这条规矩）。`p.go` 对节点位置没有偏好，内容区有同名文字时会先命中（商店里有游戏叫「我的奇妙小镇」，沿用 #305 / #386）。`p.find(..., edge_ok="tab")` 也不是「只找底栏」的写法：`edge_ok="tab"` 只在**已经命中屏底带**时决定点击坐标，搜索本身仍按控件树顺序返回第一条同名文字，内容区那条照样会先被找到——要定位底栏就用 `tab()`。

一个文件只有这些形状：导入（`from recipe_kit import step` 与文件末尾那段 `if TYPE_CHECKING:`）、模块常量（`BUILD` / `MODELS` / 走法常量 / 名单）、函数定义、模块 docstring 与注释。**模块体里不要写别的语句**——`print`、`for`、设备调用都会在导入那一刻执行，顺序与失败处理都藏进模块体，引擎与重试都看不见（`dev.recipes.module-body-shape` 守着这一条）。

脚本只拿两个协作者：`p` 是设备面（`p.start` / `p.tap` / `p.off` …，见下面两张表）；`rt` 是这一次执行，能读的是 `rt.verified`（回读确认了几项）、`rt.failed_steps` / `rt.results`（分段台账）、`rt.only`（这次只跑哪些段）、`rt.safe_mode`（是不是安全模式）。要记「回读确认了几项」就调 `rt.confirm(条数)` 或引擎注入的 `VERIFIED_SWITCHES += 条数`，别在脚本里自己累加。

`tail()` 是尾钩子：所有段跑完之后由引擎调一次，用来打收尾那几行。不定义就什么都不做；断线中止时不执行。

除 `p` / `rt` 之外的裸名字（`require` / `close_named` / `gear` 这些）都必须来自 import——真实运行不需要它们（装载时由引擎写进执行作用域），它们只是让编辑器与静态检查知道「这个名字由哪个库提供」。每条 import 指向哪个模块，就是「这个实现住在哪个库」的声明。**这些 import 写在文件末尾的 `if TYPE_CHECKING:` 块里**（`from recipe_kit import step` 是真 import，按脚本习惯放在顶部）：写在顶部会在运行时真的 import 一次，而库模块在运行时并没有这些属性。

前导不用自己写：`@step` / `require()` / `require_switches()` / `page()` / `maybe()` / `skip()` / `start_or_skip()` / `skip_in_safe_mode()` 由引擎在跑脚本时注入同的一份（`tool/recipe_kit.py`；各家族的公共导航助手另在 `tool/recipe_nav.py`、拨动策略在 `tool/recipe_strategies.py`、跨文件共用的段体在 `tool/recipe_steps.py`，[ADR-0029](adr/0029-recipe-preamble-injection.md)）。段里抛了异常由引擎记段名，客户端重试与退出码都看这份名单；脚本只写段体，别再抄一份段包装、名单或帮助函数——抄回来的副本会盖住注入的那份，两代实现又开始分叉。 <!-- rule:dev.recipes.no-local-preamble -->

同一个注入名在一个家族里有几套结构不同的实测走法时（齿轮点完要不要认落点、浏览器设置走「菜单」还是「我的」），实现各占一档住在库里，脚本只声明用哪一档：写一个模块常量（如 `GEAR_STYLE = "checked"`、`BROWSER_FLOW = "menu"`），只写偏离缺省的那一档，值认不出时调用那一刻当场报错。别把变体抄回脚本——段体按旧名字调用，抄回来就是两份实现（#1244）。常量名按名字分，不按家族分：OPPO 系用的是 `WAIT_PAGE_STYLE` / `TAP_PAGE_STYLE` / `READ_SWITCHES_STYLE` / `CLOSE_NAMED_STYLE` / `OPEN_SETTINGS_STYLE` 这一组，等待预算这类单个数字也是常量（`WAIT_PAGE_TIMEOUT`，#1245）。

关一组点名的开关之前用 `require_switches(读到的开关, 名单, 页面)` 核对（`contains=True` 表示名单是关键词，`optional` 列出本版本可能没有的名字）：缺一项就整段不动，报错里带上停在哪个页、页面摘要与当次读到的开关标题（#903）。

点开或拉起一页之后用 `page(标题, 包名, Activity)` 确认落在预期上：标题给一组时任一出现即算到页。三段判据失败时先打一行「· 「X」没找到；停在 包名/Activity；结构摘要」，再抛原来那句错——X 是这一段缺的那样东西（包名、Activity 或标题），现场走独立输出行，报错文案逐字不变，据此分清是标题改名还是页面没加载完（#939）。

整页关闭的段落（逐 App 的广告跟踪列表、应用建议卡片、文件夹底部的更多推荐）第一句写 `skip_in_safe_mode()`。整页关闭指这一页没有可点名的目标——段里还关点名开关的，那一行不动，照常跑。 <!-- rule:dev.recipes.safe-mode-page-wide-skip -->

脚本可以在模块里按需定义下面四个名字，引擎在对应时机按名字找；不定义就什么都不做。顺序无所谓（导入不再执行段），写在函数区里就行。

| 名字 | 引擎什么时候调 |
|---|---|
| `guard()` | 段入口、读锁屏之前。用于型号 / 版本守卫：`skip(原因)` 记跳过，抛异常记未完成 |
| `wrap` | 段体外面套的上下文管理器（如 `honor-WKL-AN20` 的 `wrap = safe_ui`），等价于以前手写的 `with safe_ui():` |
| `detail()` | 失败时紧跟在 `✗ 未完成：…` 后面多打一行现场摘要（`meizu-MEIZU 21 Pro` 的 `detail = page_summary`） |
| `tail()` | 所有段跑完之后调一次，收尾打印 |

分段结果由引擎记在 `rt.results` 里，脚本不用再定义 `RESULTS`。

怎么算「没跑成」，分三类：

- **可选入口**：`maybe()` / `p.entry()`，找不到返回 `False`，不算失败，继续找下一个入口。
- **必需入口**：`raise`，没找到就是这一段的失败。写成 `maybe()` 会让失败永远报成成功。
- **按约定不跑**：这一段本来就不该在这次运行里执行（型号 / 版本不符，或像「音乐」段那样必须机主手动进入）。用 `skip(原因)`，引擎接住后只打印一句「跳过」，只记跳过台账，不进失败名单。这一段要用的 App 本机没装也归这一档，判据在引擎：`Phone.start()` 在启动失败、手机在线、`pm path` 空时抛出的就是跳过类型，新脚本不用自己写 `pm path` 早退（存量 18 份里的那一批还没收，属重构）。入口在这台机器上不可达（缺配套 App，拉起后被系统转去应用商店详情页或桌面）也归这一档，用 `start_or_skip(包名, 页面, dead_ends, 原因)` 收尾（沿用 #902）；整页关闭的段落用 `skip_in_safe_mode()`（沿用 #909）。「先试直达、失败再走菜单」的助手要把跳过原样上抛（`except SkipStep` 写在宽捕获之前）：吞掉它，这一段会从跳过退化成走菜单后的空跑或假失败。 <!-- rule:dev.recipes.skip-passes-through-helpers -->

## 引擎提供的动作

### 该用哪个导航方法

拉起 App 与按文字点东西的方法名字近义、契约不同：失败时是返回 `False`、`raise` 还是记跳过，决定这一段写不写得下去。选错一个的代价是点错地方（点到开关说明行上，真把功能关了）或整段失败。失败时怎么表现只在下面这张表写一次。

| 想做的事 | 用哪个 | 失败时 |
|---|---|---|
| 拉起 App 或指定页面，并确认落在预期页面 | `p.start(包名, expect=…)` | raise，本段失败；包没装时抛的是跳过（`MissingPackage`），本段记跳过（#908） |
| 拉起 App，落点被系统转去别处时按跳过收尾 | `start_or_skip(包名, 页面, dead_ends, 原因)` | 报错里的落点命中 `dead_ends`、且是「没有进入前台 / 启动后离开前台」→ 记跳过；其余照 raise |
| 确认已经落在预期页面上（包名 / Activity / 标题） | `page(标题, 包名, Activity)` | raise，并先打一行「· 「X」没找到；停在 …；结构摘要」（#939）；同意弹窗记跳过，锁屏中止整批 |
| 点一个没有也能继续往下走的入口 | `p.entry(文字)` | 返回 False，并打印停在哪个 Activity 与结构摘要；断线、翻页走丢照常 raise |
| 点一个必须点开的换页入口（设置页、子页） | `p.enter(文字)` | raise |
| 在系统设置里搜到这一段的入口 | `p.setting(关键词, 结果)` | 返回 False，并打印没打开 / 没搜到；必须检查返回值——这一段没它就做不成时，`if not` 里要 raise，别静默空跑。搜不到会走菜单兜底时，兜底也不通同样要 raise（#819） |
| 点文字，直到屏上出现期望的文字 | `p.go(文字, 期望)` | 返回 False；「期望」本来就在屏上时，点不开也会算成功 |
| 只点不看结果（开关行、按钮） | `p.tap(文字)` | 返回 False |
| 点屏幕底部的标签 | `p.tab(文字)` | 返回 False，不会静默改点内容区里的同名文字 |

**到某个分组的入口**（系统广告、应用商店、浏览器这类）不要自己写走法：先查 `tool/entries.py` 的 `ENTRIES`（`docs/清单/入口速查.md` 是它渲染的），再用 `reach()` 试「直达页面 → 设置搜索」两档，到了返回 `"direct"` / `"search"`，都不通返回 `None`，由调用方照 `entry.menu` 走菜单或跳过。直达可以是页面，也可以是公开 Intent（`Direct.action` → `am start -f 0x10008000 -a 动作 -p 包名`），别在脚本里再抄一份 `am start -a …`。分工是「走哪个入口」归 `reach()`（`ENTRIES` 里有出处的那一条），「到了页面上怎么点」归 `Phone.*`。

`p.enter()` 只确认「换页了」，不确认「进的是对的那一页」：同一屏上另有同名入口时（小米浏览器工具栏和底部菜单弹窗各有一个「设置」，#586），点错也换页。入口先按位置收窄（弹窗那一行在屏幕下半段），点完再用 `p.in_settings_page()` 之类的落点判据核对；没对上就退回来重开，别在错页上继续找子项——那种走法不报错，只是整段 0 项。

在刚打开的菜单浮层里等入口，别用 `scrolls=0` 的 `p.tap()`：它等待期间会调 `dismiss()` 关弹窗，浮层自带的返回键、取消这类控件都可能被当成弹窗点掉，刚打开的菜单随之收起（沿用 #753 的处理；引擎已排掉 desc 读作「返回」的那一类，别的文案仍可能命中）。用 `wait.until` 等到那一行再 `p.click`，落点校验与重开见 `tool/recipe_nav.py` 里的 `_vivo_browser_settings`（已注入每份脚本，本地不用再抄一份）。

### 动作一览

下面这张表写参数与行为，失败时怎么表现只看上面那一张。

| 动作 | 作用 |
|---|---|
| `p.start(包名, activity=None, expect=None)` | 拉起 App 或指定页面；`expect` 是预期页面的文字（给一组时全部出现才算到页），落在开屏页 / 推广页就退一次（返回退出 App 时重新拉起）（#420） |
| `p.setting(关键词, 结果)` | 在系统设置里搜索关键词，点搜索结果；失败返回 `False`，返回前已离开搜索页、收起键盘并回到设置首页（#639）。失败时该不该让本段失败见上表 |
| `p.tap(文字, exact=False, scrolls=6)` | 找到文字就点；`scrolls=0` 只看当前屏，6 秒内边等边关弹窗 |
| `p.entry(文字, scrolls=6)` | 可选入口：先等当前页站稳再找；没找到时打印 Activity 与结构摘要（不含页面文字） |
| `p.await_page(预算=2.4, 轮询=0.2)` | 等当前页面画完并站稳；只等「这一页画完」，不等「换成了新页面」 |
| `p.in_settings_page()` | 当前页是不是某个 App 的设置页（焦点类名含 `Setting` 或 `Preference`，覆盖 `ThemePreferenceActivity`、`BrowserPreferencesPage` 这类）；点完齿轮用它确认真的进去了 |
| `p.enter(文字, scrolls=0, tries=3)` | 点一个会换页的入口，并确认页面真的换了：点击被弹窗淡出动画吞掉时再点。只给会换页的入口用——没换页它会再点一次，别用在开关行上 |
| `p.go(文字, 期望)` | 点文字，直到期望的文字出现。精确匹配当前屏找不到时退回包含匹配（底部标签常读作「我的，有新消息」，精确匹配「我的」返回空） |
| `p.tab(文字)` | 点屏幕底部的标签：只在屏底 15% 带内找，带内按「精确 → 逗号末段相等 → 包含」递进。底部标签用它，普通文字导航用 `p.go(文字, 期望)`；带内有同名长文案时精确优先（#386，ADR-0012） |
| `p.off(keep=[], only=None, page="")` | 关当前页开着的开关；`only` 只关这些，`keep` 保留这些。点开关本体不动的页面（只认行标题的）由引擎回退，脚本照旧用它。拨不动的开关记进引擎台账，跑完退出码为 1（#788），脚本不用自己检查返回值 |
| `p.back(n)` | 按 n 次返回 |
| `p.find(文字)` | 只找不点，返回坐标或 None |
| `p.confirm()` | 关开关时弹出确认框，点确认。没有弹窗时也要等满预算才返回（约 1 秒），两侧不用再补固定 `sleep` |
| `p.sig()` | 当前页面的文字签名，用来判断页面换没换 |
| `p.settle(before, maxwait)` | 等新页面画出来并站稳；`before` 是点击前 `p.sig()` 的值 |
| `p.tap_icon(期望文字)` | 点右上角没有文字的图标，直到期望的文字出现；点开的不是目标页就退回换下一个 |
| `p.d.shell(命令)` | 执行任意 shell 命令 |

有些页面点开关圆点不动、点整行标题才拨（Google 广告设置页就是这样）。`p.off()` 在两轮补点之后会回退到点标题，并照旧回读确认；脚本**不要**为这种页面自己写逐项点击（#608，ADR-0024）。

一段里第一个入口没找到，后面的入口只看当前屏，不再翻页，这一段几秒结束，不会乱点。

## 页面还没画出来的时候

不要自己写「反复读屏、直到页面认出来」的循环。等一个动画结束这种固定停顿用 `time.sleep` 没问题，等页面就用下面这些：

```python
before = p.sig()                     # 点之前：当前页面的签名
p.click(x, y)
p.settle(before, 1.5)                # 点之后：等页面换掉并稳住，最多 1.5 秒
```

只要「某个文字出现」时用 `p.go(文字, 期望)` 或 `p.tap_icon(期望文字)`，它们内部已经带等待。

可选入口（找不到也能继续往下走的入口）用 `p.entry(文字)`：它先等当前页站稳再找，失败时留下一行能定位的结构（停在哪个 Activity、标题与开关数、控件链），不打印页面文字。Android 17 上设置页渲染慢，直接 `p.tap` 会对着还没画完的页面报「没找到」。

机型脚本里**不要**自己实现页等待：`tool/recipe_nav.py` 已经注入一份 `wait_page()`。`recipes/oppo/PKX110` 等少数脚本里还留着本地同名定义（标题名单、超时各自不同，覆盖注入版），那是版本差异，不要照抄。

## 共享库与家族库：写哪、别写哪

公共助手住在三个注入面库里（`recipe_nav` / `recipe_strategies` / `recipe_steps`），前两个再按「谁在用」分节。**家族库**是同一个家族里 ≥2 台机型在用的实现：小米系、vivo、OPPO 系（oppo / oneplus / realme）各有一节；荣耀、魅族、三星脚本太少，不开家族库。**共享库**是跨 ≥2 个家族在用的实现：`tool/recipe_nav.py` 与 `tool/recipe_strategies.py` 里的 `SHARED` 集合就是这些名字的清单。**只是字面量不同**（标题名单、超时秒数）的，参数化后共用一份，脚本侧用模块常量把值传进去。

新机型的第一份脚本**只往家族分节加东西，或者干脆什么都不加**：能直接用共享库里已有的名字就直接用；只服务这一台机的助手留在脚本里。把单台机的写法塞进共享库，等于给一份脚本造了一个家族库，下一台机要改它时得先猜它在服务谁——所以机器守卫是「共享分节里的每个实现必须被 ≥2 个家族使用」，`docs/agents/rules.toml` 里登记为 `dev.recipes.shared-sections`。家族分节不受这条限制：它是新机型并入的入口，也是「同一算法的另一档走法」的落点。

发现引擎的某个原语（`p.off()` 的落点、`p.tap()` 的匹配、确认框的判定）在这台机上不对时，**不要在脚本里给引擎打补丁**：不要给 `p` 挂属性、不要改共享库里那份实现、不要在段体里绕过它自己点。把它写成社区问题上报或直接修引擎（`tool/phone/` 与 `tool/recipe_*.py`），脚本只负责描述这台手机上要点哪几个字。补丁留在脚本里，别的机型看不到它，引擎的下一版还会把它盖掉。

## 写机型脚本的步骤

1. 手动走一遍：

   ```bash
   python3 tool/fast.py -s S ls            # 看当前屏幕上有什么字、什么开关
   python3 tool/fast.py -s S tap 我的 设置   # 一步一步点进去
   python3 tool/fast.py -s S scan          # 到了设置页，列出所有开关
   ```

2. 把走通的路径写成 `@step`（一个段一个入口，段名尽量与词库的分组同名）。
3. 能用 activity 拉起的页面用 activity 写，最快也最稳：

   ```bash
   adb -s S shell dumpsys window | grep mCurrentFocus   # 停在设置页时查当前 activity
   ```

   写成 `p.start("包名", ".settings.XxxActivity")`。

4. 跑一遍：`python3 tool/run.py -s S recipe 软件商店`，再跑全部，记下用时，填进 README 的机型表。

写完脚本用查漏对一遍同族的词库：

```bash
python3 tool/vocab.py gaps <家族>/<型号>
```

列出同家族别的机型关过、这份脚本没写的词条，按分组列。它是自查清单，不是缺陷报告：同族的词在这台机上可能换了叫法、对应 App 没装，或者有意不关。

## 适配辅助工具（adapt）

新机型没有脚本时，用 `adapt` 四段流水线攒一份草稿（中间勾选 TSV 那一步由人做，不算一条命令）。四段都由人把关，工具不自动决定关哪些开关：

```bash
python3 tool/run.py -s S adapt survey                                          # 1. 只读试入口
python3 tool/run.py -s S adapt explore com.heytap.market com.heytap.browser    # 2. 只读探路
# 3. 编辑 探路-<型号>.tsv：末列「人工勾选」写「关」，挑出要关的开关
python3 tool/run.py adapt gen 探路-<型号>.tsv                                   # 4a. 生成草稿（不碰手机）
python3 tool/run.py -s S adapt check 草稿-<型号>.py                            # 4b. 安全模式自检
```

`survey` 拿同家族已验证过的直达页面逐条打开，报打不打得开、落在别处时实际停在哪个页面、页面上命中了同分组的哪些词条，以及同族脚本用过的 App 这台装了哪些。落在对的页面却没看到入口记录里写的判据文字时单独报一行——引擎的 `reach()` 这时会换下一档，不算这一档通了。只读：不点开关，看到协议弹窗只标注「弹着协议，没有点」。它不代替探路：探路读一屏的全部控件、产出给人勾选的 TSV，试入口只验证已知路径通不通。

`explore` 逐个打开 App 的设置页和子页，列出像广告的开关；只读，不拨开关。进了子页回不去设置页时：有界重试返回 → 重进设置页恢复 → 仍失败就明确中断本 App 并说明原因，不会死循环。

`gen` 把人工勾选的开关生成一份草稿。草稿与正式脚本同形、可以直接装载：`from recipe_kit import step` 在顶部，`BUILD` / `MODELS` 在常量区（型号身份就写在 `MODELS` 里），段用 `@step` 声明，尾钩子 `tail()` 打印回读结果，文件末尾的 `if TYPE_CHECKING:` 块声明草稿用到的注入名：

```python
from recipe_kit import step

BUILD = ""
MODELS = ["PLP120"]


@step("com.heytap.market · 设置 > 隐私")
def _():
    # 待验证：入口路径来自探路（设置 > 隐私）
    p.start("com.heytap.market")
    p.tab("我的")                  # 底栏标签一律用 tab()：go/find 会先命中内容区同名文字
    require(p.tap("设置", exact=True, scrolls=3), "未找到设置入口「设置」")
    require(p.tap("隐私", exact=True, scrolls=4), "未找到子页入口「隐私」")
    close_named(["个性化推荐"], "设置 > 隐私")


def tail():
    print(f"\n草稿自检：回读确认 {rt.verified} 项，"
          f"未完成步骤 {len(rt.failed_steps)} 个", flush=True)

from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from recipe_kit import close_named, p, require, rt
```

草稿里的开关按点名式写（`close_named([...], 页面)` 与安全模式 `recipe --ref` 兼容），`@step("...")` 的字面格式保持不变（`run.py` 的步骤名解析依赖这个格式）。关开关的壳带回读：没找齐不操作，关完回读确认。

`check` 用安全模式跑草稿：只关 `only=` 点名的开关，找不到就如实报告「哪一步没做成」，不看运行时长也不看其它页面的状态。它证明的只是「进得去、关得掉、回读确认」。

**草稿不是适配**：入口路径和开关标题全部来自探路读屏，未经人工逐步核对。自检通过后仍须人工在手机上核对每一步，再决定是否转为正式机型脚本（补上录制版本、按下面「提交 PR」登记）。不要直接放进 `recipes/`：放进去会被当成本型号的正式脚本自动匹配。

## 提交 PR

1. 新建 `recipes/<家族>/<型号>/recipe.py`。
2. 在 `docs/清单/` 对应品牌的清单里补上这个机型的差异。
3. 在 README 机型表里加一行，写明实测日期和用时。
4. 不要提交 `backups/` 目录，里面有你手机的应用列表和通知记录。

只碰机型脚本与清单的 PR 走「机型 / 清单类」的合并前检查；其中一条是「文档与生成器同步」——你的脚本与 `adapt gen` 产出的骨架保持同形，这一页说骨架长什么样，生成器就该是那个样。四条的全文见 [docs/agents/issue-tracker.md](agents/issue-tracker.md) 的「Pull requests as a triage surface」。
