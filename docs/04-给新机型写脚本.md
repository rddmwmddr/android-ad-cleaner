# 04 给新机型写脚本

机型脚本是一个 Python 文件，记录「在哪个 App、点哪几个字、关哪几个开关」。有了机型脚本，同型号的手机几分钟跑完。

## 机型脚本放在哪

```text
recipes/<品牌>-<型号>/recipe.py
```

`<型号>` 用 `adb shell getprop ro.product.model` 的输出，比如 `PLP120`、`M154FF`、`PNM-AN10`。`run.py` 按这个名字自动匹配。

同一份脚本适用多个型号时，在脚本里写 `MODELS = ["M154FF", "2608BPX34C"]`，这些型号都会用它。

没有本型号脚本时，`run.py` 会找同品牌的脚本作参考，`recipe --ref` 才会跑，客户端里默认不勾。参考脚本、版本对不上的脚本都用**安全模式**跑：只关 `only=[…]` 里点名的开关，不做整页全关。所以脚本里尽量写 `only`。

## 为什么每个型号要单独做

同一个品牌，系统小版本不同，设置页也会变。实测例子：

| 机型 | 系统 | 浏览器设置入口 | 视频设置入口 |
|---|---|---|---|
| Find N6 | ColorOS 16.0.9 | 底部 ☰ → 齿轮 | 我的 → 设置 → 个性化内容管理 |
| Find X9 Ultra | ColorOS 16.0.10 | 底部「我的」→ 设置 | 找不到「我的」 |

所以机型脚本开头写明录制时的系统版本（`BUILD`，和 `ro.build.display.id` 或小米的 HyperOS 版本号 `ro.mi.os.version.incremental` 的开头比对），版本不同时引擎会提醒并进安全模式。

`BUILD` 写具体（`OS3.0.308`）还是只写大版本（`OS3.0`），决定了这份脚本会被哪些没有专用脚本的机型借走：版本按前缀比，写细了对得上的机型少，写粗了对得上的机型多。

同一型号出了新系统版本、入口确实不同时，不改原文件，另放一份 `recipe_<系统版本>.py`（已有 `recipe_os4.py`、`recipe_android15.py`、`recipe_android17.py`）。`run.py` 只在变体的录制版本对得上时选它，其余情况仍用 `recipe.py`；变体只在同型号目录里选，不影响别的机型。

入口名在新旧版本之间会变，脚本里可以写成「有就点、没有跳过」，参考 `recipes/xiaomi-M154FF/recipe.py` 里的 `maybe()`。

**保护类开关**：「限制广告跟踪」「防止广告追踪」「关闭个性化推荐」「选择停用广告个性化功能」这类带否定词、和广告有关的开关，打开才是保护。否定词前允许「选择 / 選擇 / 点击 / 點擊」，简繁两种写法都认（#604）。`p.off()` 会把它们拨到「开」，脚本不用另外处理。

## 一段机型脚本长什么样

```python
# OPPO Find N6（PLP120，ColorOS 16.0.9）机型脚本
BUILD = "PLP120_16.0.9"          # ro.build.display.id 的开头

@step("软件商店")
def _():
    p.start("com.heytap.market", expect=("我的",))   # 拉起 App；没落在有「我的」的页面就退一次
    p.go("我的", "设置")                          # 点「我的」，直到屏幕上出现「设置」
    p.enter("设置")                               # 点「设置」并确认真的换页；被弹窗动画吞掉会重点（#286）
    if p.tap("隐私", exact=True):                 # 找到「隐私」就点，找不到会翻页
        p.off(only=["个性化推荐"], page="商店·隐私")   # 只关标题含「个性化推荐」的开关
        p.back()
    if p.tap("服务管理", exact=True):
        p.off(keep=["帮助与客服", "应用安全"], page="商店·服务管理")   # 全关，保留这两项
        p.back()
```

示例里点底栏「我的」那行抄自 `recipes/oppo-PLP120/recipe.py`，写在 `Phone.tab()` 之前。新脚本点底栏一律用 `p.tab("我的")`：`p.go` 对节点位置没有偏好，内容区有同名文字时会先命中（商店里有游戏叫「我的奇妙小镇」，#305 / #386）。

`@step` 的定义复制已有机型脚本开头那段即可。段里抛了异常要把段名记下来，否则客户端重试时不知道该重跑哪一段（退出码由抛异常或拨不动的开关决定，与段名无关）：

```python
FAILED_STEPS = []                    # 模块级，和 ONLY 放在一起

def step(name):
    def deco(f):
        ...
        try:
            f()
        except Exception as e:
            FAILED_STEPS.append(name)    # fast.py 读这个名单决定退出码
            print(f"  ✗ 未完成：{e}")
        ...
    return deco
```

怎么算「没跑成」，分三类：

- **可选入口**：`maybe()` / `p.entry()`，找不到返回 `False`，不算失败，继续找下一个入口。
- **必需入口**：`raise`，没找到就是这一段的失败。写成 `maybe()` 会让失败永远报成成功。
- **按约定不跑**：这一段本来就不该在这次运行里执行（型号 / 版本不符，或像「音乐」段那样必须机主手动进入）。用单独的子类异常（参考 `honor-WKL-AN20` 的 `SkipStep`）并在通用 `except` 之前接住，只打印一句「跳过」，不要记进 `FAILED_STEPS`。

## 引擎提供的动作

### 该用哪个导航方法

按文字点东西有七个方法，名字近义、契约不同：失败时是返回 `False` 还是 `raise`，决定这一段写不写得下去。选错一个的代价是点错地方（点到开关说明行上，真把功能关了）或整段失败。失败时怎么表现只在下面这张表写一次。

| 想做的事 | 用哪个 | 失败时 |
|---|---|---|
| 拉起 App 或指定页面，并确认落在预期页面 | `p.start(包名, expect=…)` | raise，本段失败 |
| 点一个没有也能继续往下走的入口 | `p.entry(文字)` | 返回 False，并打印停在哪个 Activity 与结构摘要；断线、翻页走丢照常 raise |
| 点一个必须点开的换页入口（设置页、子页） | `p.enter(文字)` | raise |
| 在系统设置里搜到这一段的入口 | `p.setting(关键词, 结果)` | 返回 False，并打印没打开 / 没搜到；必须检查返回值——这一段没它就做不成时，`if not` 里要 raise，别静默空跑。搜不到会走菜单兜底时，兜底也不通同样要 raise（#819） |
| 点文字，直到屏上出现期望的文字 | `p.go(文字, 期望)` | 返回 False；「期望」本来就在屏上时，点不开也会算成功 |
| 只点不看结果（开关行、按钮） | `p.tap(文字)` | 返回 False |
| 点屏幕底部的标签 | `p.tab(文字)` | 返回 False，不会静默改点内容区里的同名文字 |

**到某个分组的入口**（系统广告、应用商店、浏览器这类）不要自己写走法：先查 `tool/entries.py` 的 `ENTRIES`（`docs/清单/入口速查.md` 是它渲染的），再用 `reach()` 试「直达页面 → 设置搜索」两档，到了返回 `"direct"` / `"search"`，都不通返回 `None`，由调用方照 `entry.menu` 走菜单或跳过。分工是「走哪个入口」归 `reach()`（`ENTRIES` 里有出处的那一条），「到了页面上怎么点」归 `Phone.*`。

`p.enter()` 只确认「换页了」，不确认「进的是对的那一页」：同一屏上另有同名入口时（小米浏览器工具栏和底部菜单弹窗各有一个「设置」，#586），点错也换页。入口先按位置收窄（弹窗那一行在屏幕下半段），点完再用 `p.in_settings_page()` 之类的落点判据核对；没对上就退回来重开，别在错页上继续找子项——那种走法不报错，只是整段 0 项。

在刚打开的菜单浮层里等入口，别用 `scrolls=0` 的 `p.tap()`：它等待期间会调 `dismiss()` 关弹窗，浮层自带的返回键、取消这类控件都可能被当成弹窗点掉，刚打开的菜单随之收起（#753；引擎已排掉 desc 读作「返回」的那一类，别的文案仍可能命中）。用 `wait.until` 等到那一行再 `p.click`，落点校验与重开见 `recipes/vivo-V2547DA` 的 `browser_settings()`。

### 动作一览

下面这张表写参数与行为，失败时怎么表现只看上面那一张。

| 动作 | 作用 |
|---|---|
| `p.start(包名, activity=None, expect=None)` | 拉起 App 或指定页面；`expect` 是预期页面的文字（给一组时全部出现才算到页），落在开屏页 / 推广页就退一次（返回退出 App 时重新拉起）（#420） |
| `p.setting(关键词, 结果)` | 在系统设置里搜索关键词，点搜索结果；失败返回 `False`，返回前已离开搜索页、收起键盘并回到设置首页（#639）。失败时该不该让本段失败见上表 |
| `p.tap(文字, exact=False, scrolls=6)` | 找到文字就点；`scrolls=0` 只看当前屏，6 秒内边等边关弹窗 |
| `p.entry(文字, scrolls=6)` | 可选入口：先等当前页站稳再找；没找到时打印 Activity 与结构摘要（不含页面文字） |
| `p.await_page(预算=2.4, 轮询=0.2)` | 等当前页面画完并站稳；只等「这一页画完」，不等「换成了新页面」 |
| `p.in_settings_page()` | 当前页是不是某个 App 的设置页（类名含 Setting）；点完齿轮用它确认真的进去了 |
| `p.enter(文字, scrolls=0, tries=3)` | 点一个会换页的入口，并确认页面真的换了：点击被弹窗淡出动画吞掉时再点。只给会换页的入口用——没换页它会再点一次，别用在开关行上 |
| `p.go(文字, 期望)` | 点文字，直到期望的文字出现。精确匹配当前屏找不到时退回包含匹配（底部标签常读作「我的，有新消息」，精确匹配「我的」返回空） |
| `p.tab(文字)` | 点屏幕底部的标签：只在屏底 15% 带内找，带内按「精确 → 逗号末段相等 → 包含」递进。底部标签用它，普通文字导航用 `p.go(文字, 期望)`；带内有同名长文案时精确优先（#386，ADR-0012） |
| `p.off(keep=[], only=None, page="")` | 关当前页开着的开关；`only` 只关这些，`keep` 保留这些。点开关本体不动的页面（只认行标题的）由引擎回退，脚本照旧用它。拨不动的开关记进引擎台账，跑完退出码为 1（#788），脚本不用自己检查返回值 |
| `p.back(n)` | 按 n 次返回 |
| `p.find(文字)` | 只找不点，返回坐标或 None |
| `p.confirm()` | 关开关时弹出确认框，点确认。没有弹窗时也要等满预算才返回（约 1 秒），两侧不用再补固定 `sleep` |
| `p.sig()` | 当前页面的文字签名，用来判断页面换没换 |
| `p.settle(before, maxwait)` | 等新页面画出来并站稳；`before` 是点击前 `p.sig()` 的值 |
| `p.tap_icon(期望文字)` | 点右上角没有文字的图标，直到期望的文字出现；点开的不是目标页就退回换下一个 |
| `p.d.shell(命令)` | 执行任意 shell 命令 |

有些页面点开关圆点不动、点整行标题才拨（Google 广告设置页就是这样）。`p.off()` 在两轮补点之后会回退到点标题，并照旧回读确认；脚本**不要**为这种页面自己写逐项点击（#608，ADR-0024）。

一段里第一个入口没找到，后面的入口只看当前屏，不再翻页，这一段几秒结束，不会乱点。

## 页面还没画出来的时候

不要自己写「反复读屏、直到页面认出来」的循环。等一个动画结束这种固定停顿用 `time.sleep` 没问题，等页面就用下面这些：

```python
before = p.sig()                     # 点之前：当前页面的签名
p.click(x, y)
p.settle(before, 1.5)                # 点之后：等页面换掉并稳住，最多 1.5 秒
```

只要「某个文字出现」时用 `p.go(文字, 期望)` 或 `p.tap_icon(期望文字)`，它们内部已经带等待。

可选入口（找不到也能继续往下走的入口）用 `p.entry(文字)`：它先等当前页站稳再找，失败时留下一行能定位的结构（停在哪个 Activity、标题与开关数、控件链），不打印页面文字。Android 17 上设置页渲染慢，直接 `p.tap` 会对着还没画完的页面报「没找到」。

机型脚本里**不要**自己实现页等待。`recipes/oneplus-PHK110` 与 `oneplus-PKX110` 里的本地 `wait_page()` 是历史遗留，不要照抄 —— 引擎侧已经有一份统一的实现。

## 写机型脚本的步骤

1. 手动走一遍：

   ```bash
   python3 tool/fast.py -s S ls            # 看当前屏幕上有什么字、什么开关
   python3 tool/fast.py -s S tap 我的 设置   # 一步一步点进去
   python3 tool/fast.py -s S scan          # 到了设置页，列出所有开关
   ```

2. 把走通的路径写成 `@step`。
3. 能用 activity 拉起的页面用 activity 写，最快也最稳：

   ```bash
   adb -s S shell dumpsys window | grep mCurrentFocus   # 停在设置页时查当前 activity
   ```

   写成 `p.start("包名", ".settings.XxxActivity")`。

4. 跑一遍：`python3 tool/run.py -s S recipe 软件商店`。
5. 跑全部，记下用时，填进 README 的机型表。

## 适配辅助工具（adapt）

新机型没有脚本时，用 `adapt` 五段流水线攒一份草稿。五段都由人把关，工具不自动决定关哪些开关：

```bash
python3 tool/run.py -s S adapt survey                                          # 1. 只读试入口
python3 tool/run.py -s S adapt explore com.heytap.market com.heytap.browser    # 2. 只读探路
# 3. 编辑 探路-<型号>.tsv：末列「人工勾选」写「关」，挑出要关的开关
python3 tool/run.py adapt gen 探路-<型号>.tsv                                   # 4. 生成草稿（不碰手机）
python3 tool/run.py -s S adapt check 草稿-<型号>.py                            # 5. 安全模式自检
```

试入口拿同家族已验证过的直达页面逐条打开，报打不打得开、落在别处时实际停在哪个页面、页面上命中了同分组的哪些词条，以及同族脚本用过的 App 这台装了哪些。落在对的页面却没看到入口记录里写的判据文字时单独报一行——引擎的 `reach()` 这时会换下一档，不算这一档通了。只读：不点开关，看到协议弹窗只标注「弹着协议，没有点」。它不代替探路：探路读一屏的全部控件、产出给人勾选的 TSV，试入口只验证已知路径通不通。

逐个打开 App 的设置页和子页，列出像广告的开关；只读，不拨开关。进了子页回不去设置页时：有界重试返回 → 重进设置页恢复 → 仍失败就明确中断本 App 并说明原因，不会死循环。

写完脚本用查漏对一遍同族的词库：

```bash
python3 tool/vocab.py gaps <品牌>-<型号>
```

列出同家族别的机型关过、这份脚本没写的词条，按分组列。它是自查清单，不是缺陷报告：同族的词在这台机上可能换了叫法、对应 App 没装，或者有意不关。

生成的草稿头部带 `BUILD`/`MODELS` 元信息和通篇「待验证」标注，开关按上面的要求写成 `only=` 点名式（与安全模式 `recipe --ref` 兼容），`@step("...")` 字面格式保持不变（`run.py` 的步骤名解析依赖这个格式）。关开关的壳带回读：没找齐不操作，关完回读确认。

**草稿不是适配**：入口路径和开关标题全部来自探路读屏，未经人工逐步核对；自检只证明「进得去、关得掉、回读确认」。自检通过后仍须人工在手机上核对每一步，再决定是否转为正式机型脚本（补上录制版本、按下面「提交 PR」登记）。不要直接放进 `recipes/`：放进去会被当成本型号的正式脚本自动匹配。

## 提交 PR

1. 新建 `recipes/<品牌>-<型号>/recipe.py`。
2. 在 `docs/清单/` 对应品牌的清单里补上这个机型的差异。
3. 在 README 机型表里加一行，写明实测日期和用时。
4. 不要提交 `backups/` 目录，里面有你手机的应用列表和通知记录。
