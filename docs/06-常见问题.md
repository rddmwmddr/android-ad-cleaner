# 06 常见问题

## 会影响系统更新吗？

不会。不 root，不解锁，不改 system 分区。挂起（`pm suspend`）只是暂停一个 App，系统更新的接收和安装不受影响。

## 会影响保修吗？

不会。用到的是开发者选项和系统自带的设置项。

## 关完以后还有广告吗？

会剩一些：

| 剩下的 | 原因 |
|---|---|
| 浏览器搜索框里的轮播热词 | 设置里没有开关 |
| OPPO 软件商店的「开机必备」弹窗 | 服务管理全关后仍会弹 |
| 下拉搜索只能用百度 | 国行配置只下发一个引擎，不 root 改不了 |
| 部分 App 停在「同意协议」页 | 本项目不替你同意，没进去就没法关 |
| 新装的 App | 广告跟踪默认打开，营销通知默认打开；重跑一次通用部分 |

## 系统更新以后要重跑吗？

建议重跑。大版本更新会把部分开关恢复默认，也可能改设置页的位置。重跑前跑一次 `check`，看机型脚本版本是否对得上。

## 为什么不卸载广告 App？

国行系统应用不 root 卸不掉；`pm disable-user` 大多被系统拒绝，少数能停用的停了以后会连带坏功能。挂起可以一条命令还原，所以只用挂起。

## 挂起了哪些包会坏功能？

实测过：

| 包 | 作用 | 挂起结果 |
|---|---|---|
| `com.heytap.quicksearchbox` | OPPO 下拉搜索 | 搜索打不开，不能挂 |
| `com.coloros.assistantscreen` | OPPO 负一屏 | 卡片全没了，不能挂 |
| `com.opos.ads` | OPPO 广告服务 | 正常 |
| `com.heytap.pictorial` | OPPO 乐划锁屏 | 正常，锁屏杂志消失 |
| `com.miui.systemAdSolution` | 小米系统广告 | 正常，要配合断网 |
| `com.hihonor.quickengine` 等 | 荣耀快应用、快游戏 | 正常 |

## 脚本报「没找到」怎么办？

你的系统版本和机型脚本录制时的不一样，设置页改了名字或位置。三种处理：

1. 让 AI 照清单单步做，做完存成新机型脚本。
2. 照 [清单](清单/) 手动关。
3. 提 Issue，写明型号、系统版本、哪一段没找到。

## Windows 上客户端认不到手机？

按顺序查（[Issue #6](https://github.com/rddmwmddr/android-ad-cleaner/issues/6) 的情况查完就好了）：

1. 换一根能传数据的线，插电脑后面的 USB 口。
2. 手机下拉通知栏，USB 用途选「传输文件」。
3. 开发者选项里关掉再打开「USB 调试」，手机弹窗勾「始终允许」，点「允许」。没弹窗就点「撤销 USB 调试授权」再插一次。
4. 荣耀、华为：开发者选项里再打开「仅充电模式下允许 ADB 调试」。
5. 装手机品牌的 USB 驱动，见 [08-桌面客户端](08-桌面客户端.md#windows-驱动)。三星要装三星官方的 Samsung Android USB Driver；荣耀、华为可以装对应的手机助手获取驱动，装好后退出手机助手。
6. 关掉电脑上别的手机助手和安卓模拟器（它们会占用连接）。

0.2.4 起，Windows 上等不到手机时，客户端会只读查询设备管理器：插着的手机没有调试接口、调试接口缺驱动，会直接提示是哪一种。电脑上只有 1.0.32 这类旧版 adb 时，客户端不再使用它，改为提示下载官方 adb。

## 小米 / Redmi：大量「没找到」「点击后渠道状态未改变」，中途还会锁屏？

开发者选项里还要打开「USB 调试（安全设置）」，这一项要插 SIM 卡、登录小米账号。不开它，电脑能读屏幕，但发出的点击会被系统拒绝，设置也写不进去：机型脚本每一段都「没找到」，营销通知每一个都「点击后渠道状态未改变」，插电常亮设不上，跑一会儿就锁屏。

0.2.4 在检测页先试一次（发送一个不触发任何操作的空按键），被拒就提示打开这一项，暂不进入下一步。

## 执行到一半报 `device '<序列号>' not found`？

手机和电脑的 adb 连接中途断了。最常见的是电脑上同时开着手机助手、应用宝、360 手机助手、豌豆荚、爱思助手、刷机工具或安卓模拟器，它们自带另一个版本的 adb，会和本工具互相顶掉连接。也可能是线、接口或扩展坞接触不良。

0.2.4 会等手机回来重试一次；仍然断开，就停在这一步并说明原因，后面的步骤不再显示「成功」。0.2.3 及以前，断开后读到的是空结果，快照目录名会变成「-日期」，快应用显示「没有检测到」，这些结果都不可信，请更新后重跑。复制诊断时，会列出电脑上正在运行的其他 adb。

## 营销通知报「此 vivo 通知页的开关会影响整个 App」？

这是 0.2.3 的提示。vivo / iQOO 的应用通知总页和单个渠道页由同一个 `com.vivo.systemuiplugin` 页面承载：总页的「允许通知」会关掉整个 App 的通知，订单、聊天提醒也会一起没有；渠道页只管一个渠道。0.2.3 把这个页面整个拒绝了。

0.2.4 仍不点总页，只在从总页点进来、顶栏是渠道名的渠道页上操作，点完核对应用总开关没有变化（X300 Ultra / OriginOS 6 实测）。渠道名和 App 名相同时无法区分，会跳过，可以在手机上进入这个渠道手动关；不要用应用总开关代替。

## 复制的诊断粘贴出来是乱码？

0.2.3 及以前在 Windows 上经 PowerShell 写剪贴板，中文系统按 GBK 解码，粘贴出来是「鎻忚堪」这类乱码。0.2.4 改为直接写 Unicode 剪贴板；诊断较长时，反馈网址里也会带上手机型号、各步结果和日志节选，不再只有一句「请粘贴」。

## Mac Intel 版打不开？

0.2.0–0.2.3 的 Intel 安装包误用了按 macOS 26 编译的 Python，低于 macOS 26 的 Intel Mac 打不开（[#103](https://github.com/rddmwmddr/android-ad-cleaner/issues/103)）。0.2.4 改用最低支持 macOS 11 的 Python，打包时逐个检查包内文件的最低系统版本。macOS 10.15 及更早仍不支持。

## 「限制广告跟踪」这个开关是开还是关？

开。「限制广告跟踪」「防止广告追踪」这类开关是反着的，打开才是保护。引擎会把它们拨到「开」，不会当成广告开关关掉。

## 折叠屏跑不动？

合上手机，用外屏。展开后是左右分栏，底部有任务栏，引擎会找错位置。0.2.1 在读屏时刷新尺寸并丢掉屏幕外的节点（Issue #2 / #21），避免漏掉横屏右侧开关或点到屏幕外面，见[归档记录](归档/CHANGELOG-0.3.0及更早.md)。

## 小米搜索框一直输入 `%`？

当前源码的小米机型脚本改走菜单进入广告服务，避免依赖设置搜索。通用搜索也增加了输入框就绪、输入超时和文字校验，失败后停止输入。请升级 0.2.1，也可[从源码运行](08-桌面客户端.md#从源码运行和打包)，或照[小米清单](清单/小米-HyperOS.md)手动操作。

## vivo 客户端的清单链接打不开？

可直接打开 [vivo / OriginOS 清单](清单/vivo-OriginOS.md)。当前源码已按品牌选择具体文件并编码中文路径，vivo 和 iQOO 都指向这份清单；修复已进入 0.2.1，0.2.0 的旧链接需要更新客户端后才会改变。

## Windows 打开后显示「127.0.0.1 响应时间太长」？

见 [Issue #18](https://github.com/rddmwmddr/android-ad-cleaner/issues/18)。当前源码使用 `file://` 直接加载本地页面，不再依赖发生超时的 HTTP 服务；报告者的 Windows 11 电脑仍需复测。请优先更新到 0.2.1；暂不能更新时，可用 0.2.0 的[内置命令行](08-桌面客户端.md#windows-020-界面打不开时使用内置命令行)做只读检查，或照[手动清单](清单/)操作。

## 荣耀显示「识别不到」或「不支持」？

先区分两种情况：连接页一直没有设备，查数据线、USB 调试授权和 Windows 驱动；已经显示型号但没有机型脚本，则是该型号缺少录制路径。当前源码可主动选择同品牌参考脚本，默认不勾选；Magic5、Magic6、100 Pro、Magic7 Pro 尚不能据此算作整机适配完成。反馈时附上型号代码、系统版本、检测阶段和错误信息。

## 原生鸿蒙能用吗？

目前只能操作通过 adb 连接的安卓设备，没有实现原生鸿蒙的 HDC 调试及界面自动化。HDC 是独立的设备调试工具，见[华为文档](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V13/hdc-V13)。如果设备只提供 HDC 连接，安装安卓 USB 驱动或借用荣耀脚本不能让它兼容；不要把“荣耀”和“原生鸿蒙”当成同一套系统。

## 扫描没有营销渠道，是不是已经没有广告？

不是。只能扫描 App 已创建的通知渠道，新设备或刚重置后可能很少；数量也受应用安装和使用情况影响。App 需要先创建渠道再发送通知，创建不一定等到首次发通知时才发生，见 [Android 通知文档](https://developer.android.google.cn/develop/ui/compose/notifications/create-notification?hl=en)。正常使用后可以再次扫描；当前客户端会明确区分“没有候选”和“扫描失败”。

## 上报错误日志会发送什么？

只发送弹窗里展示的那些内容：客户端版本、电脑系统、手机型号和系统版本、各步结果、日志末尾，以及一个随机安装编号。序列号、用户目录、邮箱、手机号、IP 都已替换，不含应用列表和通知内容。服务器保存 90 天，IP 只存哈希。详见 [错误日志上报](12-错误日志上报.md)。

## 数据安全吗？

脚本在你自己的电脑上跑，不联网上传任何东西。快照存在本地 `backups/`，里面有应用列表和通知记录，不要上传到公开仓库。`.gitignore` 已排除这个目录。

## 运行时手机能用吗？

不能。脚本在点屏幕，你一碰就乱。全程保持亮屏、解锁、插线。

## 通知扫描报 QueryController / UiDevice 错误怎么办？

请更新 0.2.3。旧版扫描会不必要地启动 UiAutomation，手机端初始化失败就无法列出渠道；新版改为 adb 只读扫描。实际关闭开关仍需要读屏，先点「检查读屏连接」，失败时「复制完整诊断」提供原始异常。截图末尾的 `Failed to execute script app` 只是程序退出结果，不能用它判断手机端的具体原因。详见[客户端排查说明](08-桌面客户端.md#通知扫描出现-querycontroller--uidevice--uiautomation-堆栈)。

## 完整日志提示 already registered，广告和营销通知都失败？

手机端读屏服务已经被注册，新连接被拒绝，具体占用者不能只凭堆栈确定。0.2.3 已补本次会话释放、同机任务互斥和一次有限重试；持续冲突会跳过后续读屏步骤并保留首个错误。请退出旧版及其他手机自动化工具；仍失败时由机主手动重启手机，解锁后只开一个客户端，先点「检查读屏连接」。不需要关闭无障碍服务或清除数据。详见[恢复步骤与验证范围](08-桌面客户端.md#提示-accessibilityservicealreadyregisterederror--already-registered)。

## 读屏失败可能与 GKD、自动记账有关吗？

已有用户反馈同时暂停这两个工具后恢复操作，但具体工具和模式尚未定位。遇到 UiAutomation 已注册或读屏连接失败，请按[读屏冲突排查](11-读屏冲突与功能通知保护.md)逐项检查；只由本人暂停可暂停的自动化功能，保留依赖的辅助服务，完成后按需恢复。该说明也包含找机位通知被误关后的单渠道恢复方法。
