# 机型脚本的前导由引擎注入

基线 `cd77080`。

40 份机型脚本各自在文件头写一遍「一段怎么开始、怎么结束、失败记在哪」：段包装 `step()`、必需入口断言 `require()`、可选入口助手 `maybe()`、段过滤名单 `ONLY`、失败台账 `FAILED_STEPS`。这些副本已经分化成两代：锁屏时一代抛异常（记为未完成），一代直接返回（不留记录，结果页报「关了 0 个」）。引擎想统一这个行为，改不到已经发出去的那些脚本副本（#838）。本票只做机制、不迁移真实脚本，它是 #839 的前提。

## Decision

**前导由引擎在执行脚本时注入，脚本不再自己定义这些名字。**

- **注入而非 import。** 段包装必须绑定当次的 Phone 与这一次的执行作用域（`ONLY` 名单、两个台账都在里面），import 来的模块级函数两者都拿不到。做成 `from recipe_kit import step` 就得把 Phone 与名单当参数传下去，等于让每份脚本再写一遍绑定代码。注入后脚本拿到的是已经绑好的闭包，写法和以前一样。
- **三个执行点注入同一份**：引擎跑脚本（`fast.execute` 的 run 分支）、适配自检（`adapt.check_draft`）、测试装载（`tests/fixtures.load_recipe`）。漏掉任何一处，就会出现「生成时安全、执行时不安全」——自检通过而真跑不记账。
- **复用 `ScreenLocked` 做中止信号，不新造类。** 它在引擎里的语义已经是「停下整批、不逐项报同一个原因」，且已有机型脚本用它表达同一件事。新造一个中止类会让同一种状态有两个名字，调用方还得判断该接哪个。
- **段过滤名单在段包装被调用时从执行作用域读，不做初始化快照。** 现有测试会在装载之后重绑或清空 `ONLY` 再单独驱动某一段；WKL-AN20 另有在段内读它做自门控的写法。快照会让这两种都看不到新值。
- **失败台账是执行作用域里的同一个列表对象**，引擎收尾与适配自检都按引用读；跳过台账 `SKIPPED_STEPS` 独立，不参与退出码。
- **退出码只保留 0 与 1。** 不新增「中止」专用取值：引擎里已有的 `2` 表示「本步骤一步都没执行」，跑中中止与之矛盾；客户端内部已占用 `3` 表示跳过。失败原因由日志行表达。
- **脚本的本地定义仍然覆盖注入的名字。** 迁移之前跑任何现有脚本，用户看到的东西一个字节都不变；注入只有在新写的（或不带本地前导的）脚本上生效。

## Considered Options

- **做成可 import 的 `recipe_kit` 模块，脚本 `from recipe_kit import step`**（否）。段包装要绑定当次 Phone 与执行作用域，模块级函数拿不到；要让脚本传进去，每份脚本又得写一遍绑定代码，前导就没被收口。
- **用新造的 `Halted` / `Aborted` 异常表示中止**（否）。`ScreenLocked` 已经承担这个语义，两代脚本里也都在用它；再造一个同类只会多一种要辨认的名字。
- **初始化时把 `ONLY` 快照进段包装**（否）。现有测试与 WKL-AN20 的自门控都在装载之后读写名单，快照会让它们看到旧值，而且是那种「跑得通、只是判错段」的静默错误。
- **本票顺带迁移 40 份真实脚本**（否）。迁移会改变用户可见行为（锁屏之后剩余段从「静默跳过」变成「记未完成、退出码 1」），与「机制层行为零变化」的验收冲突；混在一票里，行为回归与机制回归的失败分不开。迁移在 #839。

## Consequences

- `tool/recipe_kit.py` 是引擎侧这份前导的唯一实现；三个执行点各加一行 `preamble(p, g)`。它不是仓库里前导的唯一副本：40 份脚本与 `adapt gen` 生成的草稿（`adapt.py` 的 `DRAFT_HELPERS`）都还自带本地定义，覆盖注入——迁移之前，这份注入只在没有本地前导的脚本上生效（#839）。
- 除了六件，执行作用域里还多两个名字：`HALTED_STEPS`（中止之后没轮到的段，`FAILED_STEPS` 的子集）与 `HALTED`（中止标记）——前者让 `report_run()` 把「因中止未执行：…」另起一行，后者让后面的段包装不再碰手机。它们不改变失败台账：第一行与 `failed_steps` 事件仍是全部段名，与 [ADR-0004](0004-engine-state-events.md) 的「同一份数据」不冲突，结果页的重试会把中止的段一起带回来（[ADR-0026](0026-retry-failed-steps.md)）。
- `SkipStep` 与 `skip()` 都按执行作用域里的当前值取，脚本只换异常类、仍用注入的段包装时也抛接同一个类。
- `CONTEXT.md` 的「未完成步骤」从「抛了异常的那一段」扩成「没跑成或没轮到的那一段」，并新增「跳过台账」词条。
- 本票不改 `docs/04` 的写脚本说明：迁移之前脚本仍要自己写前导，现在改口会让新写的脚本依赖一个还没铺开的行为。等 #839 剥掉 40 份的本地定义后再一起改。
