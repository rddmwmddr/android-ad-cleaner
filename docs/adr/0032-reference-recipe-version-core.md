# ADR-0032：固定参考与同族脚本同池比版本核心

状态：接受（#969），待真机复测。

基线 `1c2dcbb`。前置是 [ADR-0008](0008-switch-plan.md)（录制版本按前缀比）与 #942（小米底包不算录制版本）。

`tool/run.py` 的 `recipe_for()` 以前是：固定参考的 `BUILD` 前缀对得上这台设备就到此为止，`same_version_family_recipe()` 只在固定参考对不上时才被调用。可固定参考的 `BUILD` 往往写得很粗——`xiaomi-M154FF` 是 `OS4.0`，`vivo-V2547DA` 只剩 `16`——设备版本只要以它开头就算对上，同族里录在完全相同版本上的脚本从来没进过候选。`same_version_family_recipe()` 自己的说明写着「固定参考是按别的版本录的就先在同族里找一份同版本的」，但只要固定参考足够粗，这条分支就是死代码（#969）。

## Decision

**固定参考与本族候选放进同一个池子，按「版本核心」的具体程度排序。**

- 排序键：版本核心长度降序 → 段数降序 → 目录名。两条路径（固定参考匹配 / 不匹配）共用这一套，不再有「命中即返回」。
- 替换判据：候选的核心**严格长于**固定参考的核心。等长意味着两者是同一段设备版本的前缀，对这台机同样贴，保固定参考——否则目录名字母序就成了决定因素。
- 固定参考对不上这台时它不设门槛：任何匹配的候选都比它贴。这是 #319 的原行为，保留。
- 段数门槛（候选段数 ≥ 固定参考段数）对两条路径一视同仁，沿用 #319 的理由：版本对得上但更窄的脚本会让一次运行少关一类广告。
- 复用现有的 `version_core()` / `matching_device_version()`，不新增脚本元数据字段；`recipe_*.py` 变体照旧不进候选；`device_info` 缺失时不重挑。
- `check` 的「机型脚本」一行在选中的不是固定参考时追加「（同族同版本，非固定参考）」，紧随其后的「录制版本 X，这台 Y（相同／不同）」原样保留。

## Considered Options

- **同池比版本核心**（采纳）vs **只在固定参考不匹配时才挑**（现状）。后者就是本票的 bug：固定参考写粗时，更贴的那份永远选不中。
- **加「同一 Android 底包才换」的闸**（否决）。要给全部小米脚本新增 `BASE` 元数据，改动面从 `run.py` 一处扩到整棵脚本树；而且 #942 刚把底包排除出版本比对（底包整代机型共用，对「是不是同一个 ROM」零信息量），再用它当选型闸，两处口径要一起改，收益只是「换过去的把握大一点」。
- **把 `recipes/verified.toml` 的档位接进选型**（否决）。四份候选全是「部分验证」，而档位度量的是整跑覆盖面，不是布局贴合度——用覆盖面挑不出一份更适合某台机的脚本。
- **等长时按目录名或遍历顺序挑**（否决）。会让 `vivo` 的 `16.x` 设备被挑给 `vivo-V2309A` / `V2324HA`，纯属偶然，比现状差。

## Consequences

- `OS4.0.5.0.*` 的设备（Xiaomi 17 Pro Max 等无专用脚本机型）从 `xiaomi-M154FF` 换到 `xiaomi-2512BPNDAC`；`OS4.0.4.0.XHPCNXM` 从 `xiaomi-M154FF` 换到 `xiaomi-M332BF`。两者段数都是 9，过得了 #319 的门槛。
- 按现行脚本树，oppo / honor / meizu 的选型在样本设备版本上不变；vivo 与固定参考核心等长的脚本（`16`）仍保固定参考。`vivo-V2417A`（`16.2.14.1.W10`）是严格更贴的候选，报出这个版本核心的 vivo 会换到它——这是本规则想要的结果，只是上报库里抽不出 `_A_` 版本核心，有多少台会换未确认。
- `recipe_for()` 从此只有一套排序；`same_version_family_recipe()` 不再是「固定参考对不上」的补丁，而是两条路径共用的挑选（名字沿用票面，语义已从「同版本」放宽到「更贴」）。
- 用例在 `tests/test_reference_by_version.py`：`test_a_finer_recording_beats_a_matching_pinned_reference` 覆盖这条以前走不到的路径（固定参考命中后仍换到更贴的同族脚本），`test_the_suffix_comes_from_the_real_pick` 端到端验证 `check` 的后缀来自真实选型。等长保固定参考、同长度按段数、三星 / 华为不标后缀这三条在旧树上也绿，docstring 已按守卫用例说明。
- **没有真机可验。** 验收是单元回归加新旧实现的影响面对拍，真机复测进下一版 `waiting-for-verify` 清单。
