# ADR-0033：`Phone` 按阶段拆成两个基座与五个阶段

状态：接受（#1036）。第一笔（本 ADR 与两条对外契约守卫）已落地（#1037）；模块搬迁分七步
（#1038–#1044），文档与规则注册表在 #1045 收口。

基线 `f4c5df5`。前置是 [ADR-0002](0002-phone-state-interface.md)（读屏 adapter 只命名、不收窄）
与 [ADR-0020](0020-no-read-write-split.md)（否决把 `Phone` 按读 / 写切分）。

## 现状

`tool/fast.py` 的 `Phone` 是一个类：1253 行、66 个 `def`（63 个唯一方法名）、19 个 `self.` 字段写点、
69 个公开成员（45 个方法 + 24 条数据：3 个读写属性、4 个类常量、17 个实例字段）。最大的十个方法
合占 678 行，方法体合计 1163 行，`off()` 一项就占 168 行。

它同时承担连接、读屏、导航、弹窗、拨动、文本输入与启动。近期改动最密的四处——
`off()` 的回读与补点、启动后的前台归属、`dismiss` 与确认框、设置搜索——全落在这一个文件里。

三处代价：

- **改动互相踩。** 改一处行为要先确认另一阶段不会被带偏。
- **状态没有归属。** `miss` / `app` / `promoted` 是跨阶段的会话状态，长度与寿命各不相同，却与普通字段
  并列在同一个 `self` 上；谁在什么时候写它只能通读全文得知。
- **测试面浅。** 验一处行为必须造整台 `Phone`，没有真机基本验不了。

## Decision

**沿 observe → decide → act → report 的阶段轴切成 7 个模块 + 一个薄门面，落在一个新的引擎子包
`tool/phone/` 里（七个协作者各一个模块，门面单独一个）。**

| 模块 | 拥有什么 |
|---|---|
| `Connection` | 连接与生命周期：设备、串号、断线判定、锁屏等待、日志开关 |
| `Screen` | 基座第二、三层：读屏与认行、页面诊断、视口几何（`W` / `H`）、动作原语（含翻页 `scroll` / `scroll_more`），以及确认框的认法（`confirm_target()` / `residual_confirm()` / `residual_note()`） |
| `Navigator` | 导航：`tap` / `go` / `enter` / `entry` / `tab` / `back` |
| `Toggler` | 拨动会话：`off()`、`confirm()` 与它的计划、回读、补点、结局 |
| `Launcher` | 启动与落点：`start()`、前台归属、落点证据 |
| `SettingsSearch` | 设置搜索：进搜索框、输入、往返 |
| `Dismisser` | 弹窗与推广位：`dismiss()` 的退化链 |
| `Phone`（门面） | 只做转发与组合，公开名字一个不改 |

分层是三层，不是七个平级：

```
Connection  →  Screen（观测 + 动作原语 + 视口几何）  →  五个阶段  →  门面
```

三个跨阶段状态各有对象：**丢失记录**（`miss` / `missed`，被导航、启动、设置搜索写，被拨动读）、
**启动会话**（`app` / `promoted`，由启动写、被弹窗读）、**渠道会话**（四个借住的渠道字段，
渠道判定是唯一读写方）。`systemui_text` 不搬，读屏最热路径在读它。

四条硬约束：

- **`Screen` 是注入式独立对象**，构造时注入 `Connection`；五个阶段注入 `Screen`；门面只持有并转发。
  它不能是门面的私有成员——否则测一个阶段仍要造整台手机。
- **阶段不继承 `Phone`。** 继承会让 `p.*` 的命名空间与类层次纠缠，也会复制 `__enter__` / `__exit__` 语义。
- **门面禁用 `__getattr__` 反射转发。** 搬漏的方法必须抛 `AttributeError`，这是本次最想避免的失败模式；
  反射会把搬漏静默吃掉。身份字段用显式属性 + 赋值器。
- **集合字段转发成可变集合本体。** `p.promoted.clear()` 与 `p.changed.append(...)` 直接改门面持有的那个对象，
  转发成拷贝会让脚本静默失效。

## 为什么这不是「只是换个名字」

ADR-0002 与 ADR-0020 都提过同一句否决：只在 `Phone` 内部拆，只是换个名字，不减少任何一处的复杂度。
那条论证针对的是**按读 / 写拆**——读写是横切，会同时穿过五个阶段却不减少其中任何一处。本切法沿的是
另一条轴：ADR-0020 自己已经指出，「这个仓库的复杂度沿观察 → 决定 → 动作 → 报告分布」，并且已经沿这条线
切过 `row.py` / `wait.py` / `plan_switches()` / `off()` / `ChannelPage` / `events.py`。这次只是把 `Phone`
里剩下的那部分也切在同一条线上，而不是新立一条轴。

复杂度确实下降，四处可数：

1. **共享可变状态减少。** 19 个 `self.` 字段写点收成三个会话对象 + 门面上的显式转发属性；`Phone.__init__`
   里赋值的成员从 12 个降到 7 个（#1039 实测：三个对象吸收 8 个裸字段，对象本身占 3 个槽位），
   拨动会话再收走 `safe_mode` / `changed` 后是 6 个（#1040）。
2. **改动面收敛到一个文件。** 最密的四个改动区（回读与补点、启动前台、`dismiss` 与确认框、设置搜索）
   从同一文件分到四个模块，一条改动只动一个文件。
3. **环边断掉。** 现状有三条环边：`Navigator ⇄ Dismisser`（`tap` / `go` / `tab` 调 `dismiss`，
   `dismiss` 回调 `click` / `back`）与 `Navigator ⇄ Toggler`（导航调残留提示）。`Dismisser` 保持独立，
   `Navigator` 只经注入的窄接口调它；残留提示降为纯函数放进 `row.py`（#1040 已落地：
   `row.residual_note()` 拼句子，读屏与确认框判定在基座上，导航侧不再经过拨动会话）。
4. **测试面下沉。** 一处行为可以只造 `Screen` 或一个阶段，不必造整台 `Phone`；读屏替身仍从既有的
   `reader=` 构造参数下传一层，不新发明装配。

代价要说清：**对外接口宽度不变**。`p.*` 的名字一个不改，门面还要新增转发壳，所以行数的账不会因此变小。
收益在 locality、状态归属与测试面，不在这里。

## 对外契约与守卫

冻结面（本次重构一律不改）：`recipes/` 里 `p.*` 的 43 个唯一名字；构造签名
`Phone(serial, log=…, reader=…)`；context manager 行为（三处 `with Phone(...)`）；`from fast import …`
的模块级名字（`bounds` / `icon_hit` / `ScreenLocked` / `CONFIRM` / `want_state` / `Phone`）。
`tool/fast.py` 留作纯出口模块，模块级函数与常量原地不动。

两条守卫钉住这一层，钉不到内部结构——这是本次唯一允许的结构性断言：

- **门面公开成员**（`tests/test_phone_facade.py` 的 `FacadeSurfaceTests`）：45 个方法与 24 条数据的老名字
  逐条快照，方法不许变成数据，每一条都必须可赋值并可读回。少一个名字、或把它改成只读属性即红。
- **脚本访问面**（同文件的 `RecipeAccessTests`）：扫 `recipes/` 的 `p.*` 与 `from fast import …`，
  读的名字必须取得到，写的名字必须赋得进去，集合字段必须是活对象（`is` 同一个、改了就看得见）。

两条守卫都要用一次本地篡改证明会红（删一个成员 / 把属性改成只读），证明后还原，篡改不进提交。

## Considered Options

- **按读 / 写拆**（否决，ADR-0020 已论证）：横切轴，五处复杂度一处不减。
- **阶段继承 `Phone`**（否决）：`p.*` 的命名空间与类层次纠缠，`__enter__` / `__exit__` 语义被复制到七处。
- **七个阶段各配一个测试替身**（否决）：接缝越少越好。测试面下沉靠既有的 `reader=` 注入，
  协作者之间的分工由代码结构与评审保证，不由用例钉死——钉它就得加接缝。
- **`__getattr__` 反射转发**（否决）：搬漏的方法被静默吃掉，正是重构里最难发现的失败。
- **一个 `Session` 装下全部跨阶段状态**（否决）：三种寿命混在一个袋子里，正是 ADR-0002 踩过的坑。
- **重写而不是搬**（否决）：行为面是 43 个 `p.*` 名字、3261 处写法（正则在正文与注释里也算，
  AST 口径是 3210 次真实访问）与四条真机路径，没有重写的验收能力；纯重构靠对拍证
  「结构变了、行为没变」，重写证不了。

## Consequences

- 迁移分七步串行：基座 → 会话状态 → 拨动 → 启动 → 设置搜索 → 弹窗 → 导航。每步都动出口与门面转发，
  并行会在同一处反复冲突；导航排最后，它 fan-out 最大，前五个阶段搬完后它的依赖面才稳定。
- 每步合入前，该步涉及的方法必须有对拍样本且零漂移，驱动是 `tests/compare_phone_state.py`（冻结基线、
  两侧各起子进程），按步补样本。
- 渠道侧一行不改：四个渠道字段只到「收进会话对象」，渠道引擎与它那套 14 项结局词表留给后面单独的
  决定，两边同时动会让对拍证据失去意义。
- 真机不是必要证据：本次不改配方、不改门面行为，合入即关。
- 门面上的转发属性会成为新的「看起来像普通字段」的东西，但它们有显式的写者与读者
  （会话对象），这是与今天的差别所在。
